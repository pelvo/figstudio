- 2026-10-20 — PR #43 review thread (comment 4325667443, P3): the npm launcher's signal handlers turn off Node's own exit, and `child.killed` stopped a second signal from reaching a child that ignored the first, so a stuck binary could outlive a host that kills the launcher. The first SIGINT/SIGTERM/SIGHUP is still passed on; a second one, or a child still running `KILL_AFTER_MS` (2 s) later, gets SIGKILL. Three signal tests in `launcher.test.mjs` (a child that dies on the signal exits 143; one that ignores it is killed by the second signal before the timer, or by the timer after 2 s, exit 137); a stuck launcher is killed at 8 s so a regression fails instead of hanging. Checked: with the previous launcher the two escalation tests fail ("stuck") and the run exits; with the new one 9/9 pass on Node 22.23.3 and Node 26. Not checked on Windows (the shell-script tests skip there).
