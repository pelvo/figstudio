- 2026-10-22 — PR #43, headless pairing: an `https://` page opening `ws://127.0.0.1` needs Chrome's Local Network Access permission, which a headless browser cannot grant, so `npx figstudio-mcp --browser-proxy` failed there with `ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS`. The proxy now serves the `--origin` app itself (`apps/figstudio-mcp/src/web_mirror.rs`): files are fetched from the origin on first request, cached in memory (256 MiB, 128 MiB per file) and served with the `web/_headers` isolation headers, and `open_figstudio_browser` opens `http://127.0.0.1:<port>/#mcpProxyPort=…`, which reaches its own port with no permission. Loopback `Host` only, requests never leave the origin's host, `/mcp/` answers 404 (no Cloud relay). A loopback `--origin` opens directly; `--no-mirror` restores the old behaviour. New dependency: reqwest's `rustls` feature (already a dev dependency) for the HTTPS fetches.
