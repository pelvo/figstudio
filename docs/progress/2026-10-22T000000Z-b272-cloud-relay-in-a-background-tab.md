- 2026-10-22: Cloud relay in a background tab. A user reported that the browser tab often stopped answering an agent ("No browser tab connected", or 504 "Browser tab timed out"). Two causes: (1) in a hidden tab eframe runs only `App::logic`, on a timer that browsers throttle (to once a minute after a few minutes hidden), while every relay step ran in `App::ui`, so calls waited for a visible frame and the relay gave up after 30 s; (2) a closed relay socket was never reopened by itself, and the heartbeat retried at most once. Now relay calls start from the socket callback against the tabs the last frame saw (`mcp_web_calls.rs`); pool workers wake the main thread through a `BroadcastChannel` (`web_wake.rs`) to send replies and serve image reads; `App::logic` runs the relay pump while hidden; and a lost relay is retried with delays from 1 s to 60 s, at once on `visibilitychange` or `online` (`mcp_backoff.rs`). New e2e `a hidden tab answers relay calls while its frames are throttled` (it forces `document.hidden` and holds eframe's timer to 60 s) got 504 on main and passes now; it also failed with the socket-side start removed. The two reconnect specs were rewritten for the growing delays and pass. Unit tests for the delays, the wake and the reveal queue each failed with the change undone. The relay specs now open the fixture by drag and drop (the Open shortcut no longer reached the file chooser after the welcome sheet landed) and expect a revealed page to be shown rather than selected; 6 of the 7 pass locally (`wrangler dev`, Chromium 141). Not verified: the join spec, which now stops at the keyboard approval of the join dialog (UI only, not looked into); real Chrome intensive throttling; Safari and Firefox; a real Cloudflare deploy.
