### 2026-11-09T090000Z prototype-scroll-layers
- What changed and how it was checked: scrolling no longer re-renders. The renderer draws a screen in parts (`prototype::Pass`): the base with its scrolling frames empty, each frame's scrolling content whole and unscrolled, and each pinned (fixed or sticky) child. The app draws them as layers (`Tab::draw_layers`): the content moved by the scroll offset and clipped to the frame, pinned children above it, so a scroll only changes shifts. Nested scrolling frames still render as part of their outer frame's content. Render jobs carry each layer's state (no background for layers); the tile plan covers every layer (`tile_cache::Planned`, also used by the browser's GPU queue); the no-flash fallback is kept per layer. Checks: base + shifted content + pinned layers composited equal the full scrolled render pixel for pixel (fails if the base draws the content); scrolling keeps every layer's tile document and only shifts the content (fails if the scroll leaks into the layer pictures); a screen recording (30 fps) of the real file's scrolling panel shows continuous movement and no blank strip in any frame. clippy clean; the five crates' tests pass.
- Not verified: the browser build with layers; a scrolling frame with very tall content (its content layer is one large picture, tiled like any page).

### 2026-11-11T080000Z prototype-tile-budget
- What changed and how it was checked: review finding: each layer's tile plan was capped at half the cache on its own, so a Preview screen with three or more large layers could plan more tiles than the cache holds, and planned on-screen tiles evicted each other (flicker, re-render loop). `Cache::plan_layer` now plans a frame's layers in order; each still gets at most half the cache, but a later layer gets only what the frame has left (`tiles::plan` takes that cap) and drops to a coarser level when room is short. Regression test `a_frames_layers_share_the_cache_and_all_their_tiles_stay` (three layers of six tiles in a 16-tile cache) fails without the shared cap and passes with it. `scripts/check.sh` passed.
- Not verified: on screen with a real file that has several visible scroll frames. Fallback tiles of earlier levels or states can still give way to a large multi-layer plan (as before).
